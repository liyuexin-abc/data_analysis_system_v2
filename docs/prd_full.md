# 第一章 文档目标
## 1.1 编写目的
本文档用于补充际华国际数据分析平台中 知识平台 的详细产品设计，重点说明：
知识平台上如何配置业务知识；
本体、图谱、术语、指标语义、规则语义、分析方法论等知识对象之间的业务逻辑；
知识配置从草稿、校验、发布到应用调用的全流程；
知识平台各核心页面的功能、字段、交互和权限设计；
知识如何驱动智能问数、根因分析、预警、报告和 Skill 执行；
如何保证知识平台具备业务可扩展性，支撑未来新增经营分析、穿透监管、风控合规、供应链分析等多类场景。
## 1.2 设计原则
知识平台设计遵循以下原则：
| 原则 | 说明 |
| 本体优先 | 先建业务对象、属性、关系，再配置指标、规则、图谱、Skill |
| 语义统一 | 用户、AI、报表、预警、报告均使用同一套业务语义 |
| 场景解耦 | 底座提供建模能力，具体经营对象、指标、规则作为场景内容注册 |
| 配置驱动 | 尽量通过配置新增对象、关系、规则、方法论，而非修改代码 |
| 可治理 | 所有知识对象具备版本、审批、发布、审计、回滚能力 |
| 可扩展 | 通过 Domain、Object、Link、Interface、Skill 等机制支持新业务域扩展 |
| 可解释 | 所有智能分析结论必须能追溯到指标、对象、关系、规则或知识来源 |
| 权限可控 | 知识、图谱、指标、字段、动作均支持权限控制 |
# 第二章 知识平台总体功能结构
## 2.1 知识平台功能总览
知识平台由八大中心组成：

| 图谱中心 | 管理图谱模型、图谱实例、路径查询、多跳穿透、影响分析 |

| 指标语义中心 | 管理指标定义、公式、口径、维度、绑定对象、解释模板 |
| 规则语义中心 | 管理预警规则、风险分级、触发条件、处置建议 |
| 分析方法论中心 | 管理归因路径、指标拆解树、分析模板、报告逻辑 |
| RAG 知识库 | 管理制度文档、报告、FAQ、案例、经验知识 |
| 知识治理中心 | 管理版本、审批、发布、质量校验、影响分析、审计 |
## 2.2 知识平台在整体架构中的定位
业务系统数据
↓
数据分析平台：接入、治理、指标、查询、分析
↓
知识平台：本体、图谱、语义、规则、方法论
↓
Skill 编排框架：发现、编排、执行、审计
↓
应用场景：经营分析、智能问数、根因分析、预警、报告、闭环
知识平台不是孤立模块，而是连接 数据能力、AI 能力、业务场景、Skill 能力 的语义中枢。

# 第四章 知识配置生命周期
## 4.1 生命周期状态
所有知识对象，包括本体对象、关系、指标语义、术语、规则、方法论、图谱任务，均应具备统一生命周期。
| 状态 | 说明 |
| 草稿 | 新建或修改中，未对外生效 |
| 待校验 | 已完成配置，等待系统规则校验 |
| 校验不通过 | 存在缺失、冲突、依赖错误 |
| 待审核 | 系统校验通过，等待业务或数据负责人审核 |
| 已发布 | 正式生效，可被问数、Skill、页面调用 |
| 变更中 | 基于已发布版本发起修改 |
| 已停用 | 不再被新任务调用，历史版本可追溯 |
| 已废弃 | 不再使用，仅保留审计记录 |
## 4.2 生命周期流程
草稿
↓ 提交校验
待校验
↓ 校验通过
待审核
↓ 审核通过
已发布
↓ 发起变更
变更中
↓ 再次审核发布
新版本已发布
异常分支：
待校验 → 校验不通过 → 草稿
待审核 → 驳回 → 草稿
已发布 → 停用 → 已停用
## 4.3 审核规则
| 知识类型 | 审核人建议 | 审核重点 |
| 本体对象 | 业务域负责人、数据负责人 | 对象定义是否准确，主键是否合理 |
| 对象关系 | 业务专家、数据架构师 | 关系方向、基数、可穿透性是否正确 |
| 指标语义 | 指标负责人、财务/经营部门 | 口径、公式、维度、权限是否正确 |
| 规则语义 | 业务管理部门、风控部门 | 阈值、等级、处置建议是否合理 |
| 方法论 | 业务专家、经营分析人员 | 分析步骤和归因路径是否符合业务 |
| 图谱任务 | 数据负责人、平台管理员 | 实体识别、关系抽取、权限是否正确 |
| RAG 文档 | 文档归口部门 | 内容有效性、密级、适用范围 |
# 第五章 本体配置业务逻辑
## 5.1 本体配置目标
本体中心用于把际华国际的经营业务对象抽象成平台可理解、可查询、可分析、可执行的对象模型。
本体设计参考 Palantir Ontology 思路，包含：
Object 对象
Property 属性
Link 关系
Action 动作
Function 函数
Interface 接口
Security 安全
Mapping 数据映射
## 5.2 本体配置顺序
本体配置必须遵循以下顺序：
业务域 Domain
↓
对象类型 Object Type
↓
属性 Property
↓
关系 Link
↓
接口 Interface
↓
动作 Action
↓
函数 Function
↓
数据映射 Mapping
↓
指标绑定 Metric Binding
↓
发布本体版本
## 5.3 业务域配置逻辑
业务域用于对对象、指标、规则和方法论进行分组。
### 经营分析一期建议业务域
| 业务域编码 | 业务域名称 | 说明 |
| org | 组织域 | 集团、板块、二级单位、三级单位 |
| market | 市场域 | 客户、区域、行业 |
| sales | 销售域 | 合同、订单、履约 |
| finance | 财务域 | 收入、成本、利润、回款 |
| scm | 供应链域 | 采购、供应商、物料 |
| inventory | 库存域 | 库存、库龄、周转 |
| production | 生产域 | 生产任务、交付 |
| investment | 投资域 | 投资项目、资产 |
| governance | 治理域 | 预警、风险、整改任务 |
## 5.4 对象配置业务逻辑
### 5.4.1 对象配置前置条件
新增对象前，必须确认：
所属业务域已存在；
对象对应的业务含义明确；
对象主键可唯一识别；
对象存在数据来源或允许手工维护；
对象是否需要进入图谱；
对象是否支持问数、预警、报告或闭环。
### 5.4.2 对象配置字段
| 字段 | 类型 | 必填 | 说明 |
| 对象编码 | 文本 | 是 | 例如 Obj_Sales_Contract |
| 对象名称 | 文本 | 是 | 例如 合同 |
| 所属业务域 | 下拉 | 是 | sales、finance 等 |
| 对象说明 | 多行文本 | 是 | 说明对象业务含义 |
| 主键字段 | 文本 | 是 | 例如 contract_id |
| 展示字段 | 文本 | 是 | 页面和问数展示名称 |
| 是否入图 | 开关 | 是 | 是否写入知识图谱 |
| 是否可搜索 | 开关 | 是 | 是否支持全局搜索和问数识别 |
| 是否可监控 | 开关 | 否 | 是否实现可监控接口 |
| 数据权限字段 | 字段选择 | 否 | 通常为 org_id |
| 安全等级 | 下拉 | 是 | 普通、敏感、机密 |
| 负责人 | 人员选择 | 是 | 对象负责人 |
| 状态 | 系统生成 | 是 | 草稿、已发布等 |
### 5.4.3 对象编码规范

| 组织单位 | Obj_Org_Unit |

## 5.5 属性配置业务逻辑
### 5.5.1 属性配置字段
| 字段 | 类型 | 必填 | 说明 |
| 属性编码 | 文本 | 是 | contract_amount |
| 属性名称 | 文本 | 是 | 合同金额 |
| 数据类型 | 下拉 | 是 | string、decimal、date、datetime、boolean |
| 是否主键 | 开关 | 否 | 是否对象主键 |
| 是否必填 | 开关 | 否 | 数据是否必须存在 |
| 是否敏感 | 开关 | 否 | 是否需要脱敏 |
| 是否可搜索 | 开关 | 否 | 是否支持搜索 |
| 是否可筛选 | 开关 | 否 | 是否作为筛选条件 |
| 是否可聚合 | 开关 | 否 | 是否支持 sum、avg、count |
| 默认展示 | 开关 | 否 | 是否默认在详情页展示 |
| 数据来源字段 | 字段选择 | 否 | 映射到底层数据字段 |
| 质量规则 | 多选 | 否 | 非空、唯一、范围校验等 |
| 权限标签 | 下拉 | 否 | 普通、敏感、机密 |
### 5.5.2 属性质量校验规则
| 规则 | 示例 |
| 非空校验 | 合同编号不能为空 |
| 唯一校验 | 合同 ID 不允许重复 |
| 类型校验 | 合同金额必须为数值 |
| 范围校验 | 履约率应在 0-100% 之间 |
| 枚举校验 | 合同状态必须在指定状态中 |
| 关联校验 | 合同客户必须存在于客户对象 |
| 时间校验 | 回款日期不能早于合同签约日期 |
| 权限校验 | 敏感字段必须配置权限标签 |
## 5.6 关系配置业务逻辑
### 5.6.1 关系配置前置条件
新增关系前，必须满足：
源对象和目标对象均已存在；
源对象和目标对象主键明确；
关系字段或关系抽取规则明确；
关系方向明确；
关系基数明确；
是否支持下钻和入图明确。

## 5.7 接口配置业务逻辑
接口是支撑业务扩展的关键机制。
一个对象只要实现某个接口，就能被平台通用能力识别。
### 5.7.1 推荐接口
| 接口编码 | 接口名称 | 说明 |
| If_Searchable | 可搜索对象 | 可被全局搜索、智能问数识别 |
| If_Drillable | 可穿透对象 | 可被下钻分析和图谱路径调用 |
| If_Monitorable | 可监控对象 | 可被预警规则引擎监控 |
| If_Attributable | 可归因对象 | 可参与根因分析 |
| If_Reportable | 可报告对象 | 可进入报告模板 |
| If_Riskable | 可风险评估对象 | 可计算风险等级 |
| If_Closable | 可闭环对象 | 可执行确认、派单、关闭等动作 |
| If_GraphNode | 可入图对象 | 可写入知识图谱 |
### 5.7.2 接口配置字段
| 字段 | 类型 | 必填 | 说明 |
| 接口编码 | 文本 | 是 | If_Monitorable |
| 接口名称 | 文本 | 是 | 可监控对象 |
| 接口说明 | 文本 | 是 | 描述接口用途 |
| 必需属性 | 多选 | 是 | 实现接口必须具备的字段 |
| 支持函数 | 多选 | 否 | 可调用的函数 |
| 支持动作 | 多选 | 否 | 可调用的动作 |
| 适用对象 | 多选 | 否 | 已实现该接口的对象 |
| 权限要求 | 多选 | 否 | 调用该接口所需权限 |
### 5.7.3 接口扩展示例
未来新增“投资项目”对象，只需实现：
If_Searchable
If_Drillable
If_Monitorable
If_Reportable
If_Riskable
则投资项目自动具备：
可被智能问数识别；
可进入图谱穿透；
可被预警规则监控；
可进入报告；
可参与风险评估。
这就是本体业务可扩展性的核心。
# 第六章 图谱配置业务逻辑
## 6.1 图谱配置目标
图谱中心负责把本体中的对象类型和关系类型实例化为图结构，支撑：
多跳穿透；
影响范围分析；
风险传播；
根因分析；
关联对象查询；
智能问数路径规划；
报告证据链生成。
## 6.2 图谱与本体关系
| 层级 | 作用 | 示例 |
| 本体 | 定义对象和关系类型 | 合同、客户、合同属于客户 |
| 图谱 | 存储具体对象实例和关系 | 合同 C001 属于客户 A |
| 图算法 | 计算路径、影响、中心性、传播 | 客户 A 影响 3 个合同、2 个单位 |
## 6.3 图谱配置流程
选择图谱场景
↓
选择入图对象
↓
选择入图关系

## 10.4 利润归因方法论示例
方法名称：利润归因分析方法
分析步骤：
1. 计算本期利润与对比期利润差异；
2. 拆解收入、成本、费用、其他收益影响；
3. 计算各因素贡献度；
4. 对收入下降穿透合同、订单、客户；
5. 对成本上升穿透采购、物料、供应商；
6. 对费用上升穿透费用科目和责任单位；
7. 生成 Top 原因和管理建议；
8. 支持生成利润归因报告或派发整改任务。

# 第二十五章 总结
知识平台是际华国际数据分析平台中最关键的语义底座。其核心价值不在于简单存储知识，而在于通过 本体、图谱、指标语义、规则语义、分析方法论和 RAG 知识库，把业务知识转化为 AI 和 Skill 可理解、可调用、可执行的结构化能力。
最终形成：
业务对象可建模
业务关系可穿透
指标口径可解释
分析路径可配置
风险规则可治理
知识图谱可推理
AI 回答可追溯
业务场景可扩展
在本项目中，知识平台应坚持：
底座提供知识建模和运行能力；
经营分析知识作为场景包注册；
未来新场景通过新增业务域、本体对象、图谱关系、指标语义、规则方法论和 Skill 实现扩展。
这样既能支撑当前经营分析项目快速落地，也能为后续穿透监管、风控合规、供应链分析、投资分析等场景提供长期可扩展能力。
